\section{Learning the Basics of PyTorch}\label{sec:basics}
\subsection{Multi-layer Perceptron}
In this first part, we started by setting a seed for reproducibility, and then importing the Fashion-MNIST dataset from \texttt{torchvision.datasets}. The training and test datasets were imported separately, and the training dataset was split into two subsets: what we will use for training (90\%), and validation (10\%). Setting batch size to 64, we created data loaders that will then load the data into the models.

To start off the systematic experimentation, we used a baseline model with the following parameters: \texttt{hidden\_size} \(= 256\), \texttt{dropout} \(= 0.2\), \texttt{optimiser} \(=\) \texttt{SGD}, and \texttt{learning\_rate} \(= 0.01\). For validation, 10 epochs were used to get a good feel for the accuracy without overfitting. The experimentation is done sequentially with a small amount of values for each hyperparameter, more as a show of proof than to find the all-time highest possible accuracy. 

In the first round, only the activation function was varied, while keeping the other parameters fixed. The following activation functions were used.
\begin{description}
	\item[ReLU]
		\[
		f(x) =
		\begin{cases}
			x & x \ge 0 \\
			0 & \text{otherwise}
		\end{cases}
		,\] 
	\item[Leaky ReLU]
		\[
		f(x) =
		\begin{cases}
			x & x \ge 0 \\
			mx & \text{otherwise}
		\end{cases}
		,\] 
	\item[GeLU]
		\[
		f(x) = x \cdot\Phi(x)
		.\] 
\end{description}

Leaky ReLU resulted in the highest validation accuracy of 0.8857. See Table \ref{tab:mlpactivations} for the results of the different activation functions.

Continuing, we varied the learning rate. The following values were used for the learning rate [0.001, 0.01, 0.1]. Learning rate \(= 0.001\) resulted in the highest validation accuracy of 0.8872. 

The size of the hidden layer was also varied. The following hidden sizes were tested: 128, 256, and 512. From the results, the hidden size of 256 was the best, with a validation accuracy of 0.8560.

Finally, we tried out dropout values of 0.0, 0.2, and 0.5. Dropout \(= 0.0\) resulted in the highest validation accuracy of 0.8925. The top 3 performing models were then retrained on the train set, and tested on the test set. The results are shown in Table \ref{tab:mlptest}. The best performing model was the one with Leaky ReLU, Adam, learning rate \(= 0.001\), hidden size \(= 256\), and dropout \(= 0.0\), with a test accuracy of 0.8881.

The multi-layer perceptron model works by assigning weights to pixels, in comparison to convolutional structures, which takes into account neighbouring pixel values as well. This means that the network tries to learn weights by pixel, which is a strength for values that are invariate, applying roughly to the Fashion-MNIST dataset as images are centred and approximately at the same location, as compared to CIFAR-10, where the images' constituents move around within the images, and aren't always at the same location, which doesn't lead to a high accuracy.

Adding more layers and giving the network a capability to be more flexible would help increase accuracy, but the point remains that MLPs aren't the best tools for images.

Within the three results, a dropout of 0.2 does worse than no dropout, which may be because MLP needs all its capacity to perform, and dropout randomly sets some activations to 0 to prevent overfitting, which is not happening in this case, and hence dropout does not help performance.

This could be due to the fact that in essence, Fashion-MNIST is a much simpler task, where the items of clothing are centred, and single-channel, and there is possibly a high level of separation between classes. The images of CIFAR-10 are not only RGB, but more complicated, and not as well separated. SGD performs much worse than Adam, which could be due to a weakly-trained learning rate on CIFAR, as opposed to Adam, which generalises better and isn't as dependent on the learning rate, as it uses the moments to adapt. While this difference is large, there is not much between Adam and AdamW, which may be due to both not overfitting, hence the decay is not a huge advantage.

Within the Adam optimiser, lowering the decay enables it to adapt faster, which may make it perform better on a complex dataset. I was not able to vary the architecture as much as I would've liked to, but adding more convolutional kernels may help the models to generalise better to the more complicated CIFAR-10 dataset.
